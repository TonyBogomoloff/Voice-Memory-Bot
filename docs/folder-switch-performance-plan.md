# План ускорения переключения папок

База анализа: production `69dd6f342f2d10bee476f110c2a5958940100f09`, 25.10.2026.
В снимке базы 6 текущих сообщений и 153 старых связи ИИ; повторная очистка
заново формирует 153 удаления. Чтение SQLite занимает доли миллисекунды.

## Порядок выполнения

- [x] 1. Исправить повторное удаление: исключать уже удалённые и запрещённые
  сообщения, завершать учёт удалённого сообщения, сохранять историю ИИ,
  несохранённые исходники и возможность повторить временно неудачное удаление.
- [x] 2. Удалять сообщения пакетами до 100 ID через `deleteMessages`.
  Сохранять точные ID и исключения; при отказе отдельного сообщения безопасно
  разбирать пакет, при сетевой ошибке не забывать незавершённую очистку.
- [x] 3. Показывать последние 8 записей и добавить переход к более ранним/новым
  страницам. Сохранять хронологию внутри страницы, фотографии и полные тексты.
- [x] 4. Объединять подряд накопившиеся переключения папок: отображать последний
  выбор, не перескакивая через заметки, команды или действия другого пользователя.
- [ ] 5. Обновлять выбор папки и меню до долгой очистки; ускорить пробуждение
  отложенного обновления после обработки. Сохранить защиту исходников и порядок
  операций. Добавить длительности этапов без текстов заметок и секретов в логах.

## Проверки и публикация каждого пункта

1. Регрессионные тесты изменённого поведения и связанные целевые проверки.
2. Обновление этого файла: что выполнено и результаты проверок.
3. Отдельный commit и push в существующий `origin/main` только fast-forward,
   с сохранением параллельных изменений и сверкой production.
4. Проверка кандидата; полный suite при интеграции и изменении общих потоков.
5. Деплой под `.deploy.lock` с проверкой SHA/хешей, резервной копией исходников,
   квитанций и SQLite, ожиданием окончания обработки и возможностью отката кода.
6. Проверка manifest, active/running, healthz, ошибок, очереди и сохранности архива.

Конфиги, ключи, авторизация и архив не входят в коммиты/замену файлов.
Сокращение числа запросов проверяется отдельно от фактического времени Telegram.

## Ход выполнения

План записан до изменений кода. Выполнение — последовательно, отдельными коммитами.

### Пункт 1 — учёт удалений

Удалённые ID исключены из восстановления старых связей ИИ; после успешного
удаления/ответа «не найдено» Telegram-связь удаляется, архивный контекст остаётся.
Запрещённые удаления больше не повторяются при обычном переключении.
Проверки: 34 целевых и 332 полных теста прошли; Ruff изменённых файлов прошёл.
Общий Ruff обнаружил два ранее существовавших замечания к импортам в
`test_message_edits.py` и `test_message_folder.py`; эти файлы не менялись.

### Пункт 2 — пакетная очистка

205 сообщений удаляются тремя пакетами (100 + 100 + 5). Несохранённые исходники,
команда выбранной папки, заблокированные ID и другой пользователь исключены.
Отказ в удалении разбирается по ID, сетевой сбой сохраняет квитанции для повтора.
Проверки: 43 целевых и 335 полных тестов прошли; Ruff изменённых файлов прошёл.
Пункт 1 опубликован как `6193f0c`: manifest, healthz, SQLite и 289 файлов архива проверены.

Интегрировано параллельное оформление `3412d57`; повторный полный прогон: 346 passed.

### Пункт 3 — страницы записей

Открываются последние 8 записей, внутри страницы сохраняется хронология.
Кнопки «Раньше» и «Новее» показывают остальные страницы; устаревший номер
ограничивается последней страницей. Фотографии и полный архив сохраняются.
Проверки: 47 целевых тестов прошли, включая переходы по всем страницам, фото
и неизменность данных; Ruff прошёл. Пункт 2 опубликован как `89ab0ec`, все
проверки manifest, службы, SQLite, очереди и архива прошли.

### Пункт 4 — очередь переключений

Объединяются только подряд накопившиеся корректные кнопки папок одного
пользователя. Заметка, команда, callback, чужой пользователь или устаревшая
кнопка останавливают объединение. Учитываются подписи нового оформления.
Пропущенные команды убираются, ошибки/прерывания сохраняют события в SQLite.
Проверки: 93 целевых и 356 полных тестов прошли; Ruff прошёл.
Пункт 3 опубликован как `c34656e`, серверные проверки прошли.
