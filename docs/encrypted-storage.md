# Шифрованное хранилище Voice Memory Bot

Содержимое и имена файлов всей установленной рабочей папки защищает gocryptfs
в обычном forward-режиме: AES-256-GCM для содержимого, AES-256-EME для имён.
Включены SQLite и WAL, оригиналы, тексты, фото, очередь, конфиг бота, предыдущие
релизы и резервные копии. Приложение продолжает пользоваться обычными файлами
через закрытое FUSE-подключение, доступное владельцу службы.

Это защита данных на диске, не E2EE. При работающем боте пользователь службы и
root могут читать подключённое хранилище. Временно ключ разблокировки хранится
на том же сервере, отдельно от бота: кража и хранилища, и ключа снимает защиту.
Размеры файлов, времена и структура каталогов полностью не скрываются.
Telegram и используемые ASR/ИИ-провайдеры по-прежнему получают необходимые для
обработки данные. Их копии эта настройка не шифрует.

## Установленная схема

- Прежний путь: `/home/tony/Desktop/_code/voice_memory_bot` — ссылка на рабочую
  папку внутри подключённого шифрованного хранилища.
- Зашифрованные файлы: `/home/tony/.local/share/voice-memory-storage/cipher`.
- Подключение: `/home/tony/.local/share/voice-memory-storage/open`.
- Ключ: `/home/tony/.config/voice-memory-vault/storage.key`, права `0600`,
  родительский каталог `0700`. Значение не выводить в команды, логи или чат.
- Настройки подключения: соседний `storage.json`; содержит только пути и
  идентификатор хранилища. Ключ и этот каталог не попадают в копии бота.
- Независимый загрузчик и gocryptfs: `~/.local/libexec/voice-memory-storage/`.
  `package-receipt.json` фиксирует версию пакета Ubuntu и SHA-256 пакета/бинарника.
- Служба `voice-memory-storage.service` открывает хранилище при запуске.
  Бот зависит от неё и проверяет тип подключения и идентификатор хранилища.
  При отсутствии ключа/подключения запуск завершается ошибкой, пустой открытый
  архив автоматически не создаётся.
- `.private-tmp`, `.logs` и отдельный `.codex-runtime` находятся внутри
  шифрованной папки. Авторизация Codex остаётся ссылкой на существующий вход.
  Текстовые вызовы остаются `--ephemeral`. Журналы ограничены ротацией.
  Для обеих служб запрещены core dump и swap; SQLite временные таблицы в RAM.

## Проверка и обслуживание

```sh
python3 ~/.local/libexec/voice-memory-storage/storage.py status
systemctl --user status voice-memory-storage.service voice-memory-bot.service
python3 /home/tony/Desktop/_code/voice_memory_bot/scripts/deploy_guard.py --help
```

Обычный перезапуск бота не закрывает хранилище. Перезапуск хранилища останавливает
и перезапускает зависимого бота; сначала дождись пустой очереди. Не отключай FUSE
принудительно во время работы с SQLite.

Деплой остаётся через `scripts/release.py`: `.deploy.lock`, проверка текущего SHA,
полный набор тестов, Ruff, пробная миграция, резервная копия и квитанция.
Подготовка кандидата также держит `.deploy.lock`, чтобы тестовые файлы не менялись
параллельно переносу хранилища. Поддержка
ссылки допускается только для корня приложения: ссылки внутри кандидата по-прежнему
не разрешены. Пробные копии SQLite создаются рядом с базой, внутри шифрования.

При копировании для внешнего резервирования копируй `cipher` вместе с
`gocryptfs.conf`, предварительно остановив бота для согласованной копии SQLite.
Не добавляй `storage.key` в этот архив. Копия подключённого каталога `open` или
прежнего пути приложения будет расшифрованной. Ключ нужно отдельно сохранить на
доверенном устройстве: без него (или recovery key) восстановление невозможно.

Чтобы впоследствии изменить место ключа, сохрани его байты без изменения в новом
защищённом месте, укажи новый `key_file` в `storage.json` и проверь открытие.
Удаляй старую копию только после проверки восстановления. Если ключ больше не
хранится на сервере, для следующего запуска потребуется отдельный механизм
доставки в память/внешний сервис ключей — простой перенос файла этого не решает.
Не запускай повторный `-init` и не генерируй новый ключ для существующего архива.

## Первичная миграция и восстановление

После установки проверенного пакета gocryptfs и публикации коммита:

```sh
python3 scripts/encrypted_storage.py init
python3 scripts/encrypted_storage.py install
python3 scripts/migrate_encrypted_storage.py --expected-sha FULL_INSTALLED_SHA
```

Мигратор блокирует деплой, ждёт очередь, останавливает только бота, копирует всю
папку и сравнивает каждый файл, режим доступа и ссылку. До переключения создаёт
и полностью проверяет архив отката внутри зашифрованного хранилища. После
переключения проверяет SQLite, записи, исходники, конфиги и запуск Telegram.
Открытый исходный дубликат удаляется только после успешных проверок; квитанция
находится в `encryption-receipt.json`. Статус незавершённой миграции хранится вне
приложения в `~/.config/voice-memory-vault/migration-state.json`.

При сбое после переключения не подменяй базу старой копией: могли поступить новые
сообщения. Сохрани обе папки и сначала восстанови подключение/запуск. При сбое до
переключения исходная папка остаётся на месте, бот запускается с прежними данными.

Удаление старого открытого дубликата не гарантирует уничтожение ранее записанных
блоков SSD, внешних снимков и старых системных журналов. Общие журналы сервера и
копии за пределами папки бота эта миграция не удаляет. На этом сервере системный
раздел уже защищён LUKS; это отдельный слой, а не замена файловому шифрованию.

Описание криптографии и ограничений:
[gocryptfs cryptography](https://nuetzlich.net/gocryptfs/forward_mode_crypto/),
[threat model](https://nuetzlich.net/gocryptfs/threat_model/).
