# Односторонний экспорт Voice Memory → Obsidian

[Установка и использование плагина](../plugins/obsidian/README.md) · [План](obsidian-export-plan.md)

## HTTP v1

Сервер: `https://audio-notes.korobkoff.com`. Бот слушает только `127.0.0.1:8788`; HTTPS обслуживает отдельный Cloudflare Tunnel. API не предоставляет чтение произвольных файлов или запись/удаление заметок. CORS браузеру не открывается: плагин использует штатный `requestUrl` Obsidian. Сторонние ссылки из содержимого не запрашиваются плагином.

| Метод и путь | Назначение |
| --- | --- |
| `GET /healthz` | Публичная версия протокола, без состояния архива |
| `POST /v1/pair` | JSON `{code, name}` → `{schema_version, device_id, token, scope}` |
| `GET /v1/notes?cursor=<id>` | Страница до 50 записей, `next_cursor`, число `pending` |
| `GET /v1/notes/<id>/document?sha256=<hash>` | Точные Markdown-байты указанной версии |
| `GET /v1/notes/<id>/media?sha256=<hash>` | Проверенные байты оригинала |
| `GET /plugin/<name>` | Только `main.js`, `manifest.json`, `styles.css`, `voice-memory.zip` |

Все `/v1` кроме подключения требуют `Authorization: Bearer <token>`. Ключ передаётся только заголовком, не URL. Коды и ключи в SQLite хешированы; код одноразовый, 10 минут, новый код отменяет предыдущий того же владельца. Устройство получает область владельца и, при выборе, одной папки. Максимум 10 устройств на владельца; отзыв действует на последующие запросы. Удаление разрешённого пользователя из конфигурации прекращает доступ его устройств. Для экспорта всей базы нужны явно отдельные коды каждого владельца.

Ответы помечены `Cache-Control: no-store`. Тексты, ключи и заголовки запросов не записываются в access log. Cloudflare завершает HTTPS и видит проходящий трафик. Лимиты: 600 запросов/мин на устройство, 10 подключений/мин на IP и 60/мин глобально; `429` с `Retry-After: 60`. `401` означает отсутствующий/недействительный доступ, `404` — недоступную запись, `409` — изменившуюся/обрабатываемую запись или непроверенное медиа. Плагин повторяет получение позже, не помечая неудачные записи как сохранённые.

Пагинация по стабильному ID, проход повторяется при следующем открытии/проверке. Это не транзакционный снимок всего архива: запись, добавленная или изменённая между страницами, может попасть в следующий проход. Изменение SHA между списком и скачиванием даёт `409`. Удаления не передаются в vault.

## Файлы и конфликты

Модель документа общая для ZIP и API: `format: voice-memory-obsidian`, `schema_version: 1`. У каждой записи `note_id`, `folder_id`, относительный `path`, `bytes`, `sha256`, `kind: note` и `attachments`. Вложение имеет те же идентификаторы файла и `kind: attachment`. Оригинал называется `attachments/<note_id>/<sha256>.<ext>`. Исходные расшифровки сохраняются рядом с текущим содержимым; служебные ключи и Telegram file IDs не экспортируются.

Каждая ZIP-часть содержит `manifest-NNN.json` с точным списком файлов. Плагин проверяет завершённость ZIP, размер, допустимые пути, SHA и состав до записи. Не хватает вложения — соответствующая заметка ждёт остальные части. Максимум 200 МБ выбранных ZIP/распакованных данных за раз, 64 МБ на файл и 8 МБ на Markdown. API за один проход скачивает до 200 МБ; уже сохранённые файлы повторно не скачиваются. Для очень больших экспортов используй отдельные папки. Выход за папку, скрытые пути и запись в `.obsidian` запрещены.

Файл меняется через `Vault.process` только при совпадении с последней сохранённой версией; иначе новая серверная копия получает отдельное имя. Состояние записывается после сохранения заметки. Восстановление по YAML ID учитывает переименования внутри папки. ZIP никогда не заменяет отличающуюся версию. Удалённых пользователем файлов нет в состоянии удаления, поэтому они могут загрузиться снова.

## Развёртывание

1. Проверь текущий серверный `release.json`, интегрируй его SHA и `origin/main`, проверь Python и сборку плагина. `scripts/check_obsidian_package.py` проверяет совпадение опубликованных файлов с ZIP и версий.
2. Убедись, что серверная `.venv` содержит зависимости `requirements.txt`. Дополнительные пакеты не требуют изменения секретных конфигов.
3. В отдельном drop-in `voice-memory-bot.service.d/obsidian.conf` укажи `Environment=VOICE_MEMORY_OBSIDIAN_URL=https://audio-notes.korobkoff.com` и `Environment=VOICE_MEMORY_OBSIDIAN_PORT=8788`. Выполни `systemctl --user daemon-reload`. Перезапуск выполняет штатный guard.
4. Подготовь/установи коммит через `scripts/release.py prepare/deploy <sha> <base>`. Для подготовки без отправки сообщений используй `prepare <sha> <base> --cached-videos-only`: кэш существующих видео должен быть готов. Подготовка квитанций видео не запускает миграции рабочей базы. Guard сохраняет SQLite, исходники и квитанции, ждёт пустую очередь, проверяет хеши и службу. Миграция 4 добавляет только таблицы подключения; при откате на схему 3 возвращается маркер версии после проверки прежних объектов, но все строки и новые файлы сохраняются.
5. Используй отдельный туннель `voice-memory-obsidian` и `~/.cloudflared/voice-memory-obsidian.yml`: `tunnel`, `credentials-file`, ingress для подтверждённого hostname → `http://127.0.0.1:8788`, завершающее правило `http_status:404`. Секреты туннеля остаются только на сервере; существующий общий `config.yml` не меняется. Шаблон unit: `deploy/voice-memory-obsidian-tunnel.service.in`.
6. После успешного запуска API подключи DNS и отдельную службу туннеля. Проверь публичный TLS, `/healthz`, `401` без ключа, подключение/чтение/отзыв временного устройства, SHA опубликованного ZIP, `active/running`, `NRestarts=0`, SQLite и очередь. Не печатай содержимое заметок или ключи в квитанции.
7. Для BRAT создай tag, точно совпадающий с версией плагина (например `0.1.0`). Workflow `obsidian-release.yml` проверяет и публикует уже собранные, закоммиченные assets. GitHub Release не означает публикацию в общем каталоге Obsidian.

Публичный адрес обслуживает API экспорта и пакет плагина. Старый Mini App не восстанавливается. Фоновую работу закрытого приложения на iOS/Android не обещаем; физические телефоны требуют отдельной ручной проверки.
