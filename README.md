# Voice Memory Bot

Личный Telegram-архив голосовых и текстовых заметок по проектам. Собственные папки,
постоянное меню кнопок внизу чата, поиск и экспорт PDF/Markdown/аудио.

## Запуск

Нужны Python 3.11+, `ffprobe` из ffmpeg и актуальный Codex CLI с `--ignore-user-config`.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pip install --no-deps -e .
cp config.example.json config.json
```

В `config.json` заполни `allowed_user_ids` (числовые Telegram ID),
`bot_token_your_audio_notes` и `groq_voice`. Конфиг исключён из Git. Файл должен быть доступен
только пользователю сервиса: `chmod 600 config.json`.

Для существующего общего конфига секреты можно не копировать:

```bash
.venv/bin/python -m voice_memory_bot check --config config.json --secrets /точный/путь/config.json --live
.venv/bin/python -m voice_memory_bot run --config config.json --secrets /точный/путь/config.json
```

В общем файле читаются только `bot_token_your_audio_notes` и `groq_voice`. Параметры приложения,
список пользователей и `data_dir` читаются из локального `--config`. Пустой список пользователей
запрещён: этот MVP рассчитан на частный доступ через подписку владельца.

`check --live` проверяет конфиг, `getMe`, наличие webhook и тип входа Codex. Он не отправляет
сообщения и не доказывает работу распознавания или генерации. Существующий webhook не удаляется
автоматически, а второй процесс для того же `data_dir` не запускается.

## Telegram

Темы Telegram не нужны. Если Threaded Mode был включён, его можно выключить в BotFather
после обновления; существующий архив и названия папок сохраняются. Старые привязки к темам
остаются только как история доставки и для отдельно подтверждаемой полной очистки.

- `/start` показывает до четырёх закреплённых папок (по две в ряд), «📂 Все папки» и «☰ Меню».
  Активная папка отмечена ✓; нажатие выбирает её для записи и обновляет отметку.
- «☰ Меню» / `/menu` открывает кнопки записей, создания папки, поиска, ИИ, экспорта и настроек.
- В карточке папки «📌 Закрепить внизу» / «📌 Убрать снизу» меняет нижнюю клавиатуру.
  Закрепления сохраняются в SQLite. При обновлении первые четыре существующие папки
  (сначала «Входящие») появляются внизу; новые занимают свободное место, если оно есть.
  Переименование и удаление обновляют клавиатуру. Устаревшая кнопка не создаёт заметку.
- Открытие папки в списке выбирает её для следующих голосовых, текстов и фото. Выбор хранится
  в SQLite, отдельно для каждого пользователя, и переживает перезапуск. Если папок нет, бот просит назвать первую.
- Папка фиксируется при приёме записи: смена выбора во время распознавания не меняет назначение
  уже принятого голосового. Старые темы Telegram и слова в записи не переопределяют выбор.
- «＋ Новая папка» / `/new Название` создаёт папку в общем архиве и выбирает её.
- В карточке папки доступны записи, переименование, экспорт, режим ИИ и удаление.
  Любую папку, включая «Входящие» и последнюю, можно удалить после подтверждения.
  Записи, оригиналы, версии и история ИИ остаются в архиве, доступны через поиск и экспорт.
  Во время обработки/экспорта удаление отложено.
- «📝 Записи» / `/notes` показывает содержимое выбранной папки; «🔎 Поиск» ищет по всему архиву.
- «Отмена», переход по меню или `/cancel` отменяет запрос названия/поиска. Нажатия кнопок
  не сохраняются как заметки и не отправляются ИИ.
- «Переместить» меняет папку записи в архиве и убирает её прежние сообщения из чата.
  «Удалить» удаляет выбранную запись, исходный файл и известные сообщения. «ИИ» принимает задание к записи.
- `/export` — весь архив; экспорт отдельной папки доступен в её карточке.
- `/settings` — общее меню настроек ИИ и экспорта PDF / Markdown.
- `/delete_all` или «🗑 Удалить всё» в меню — удалить все папки и сообщения после подтверждения.

## Удалить всё

Подтверждение действует 10 минут; «Отмена» и `/cancel` его отменяют. Очистка удаляет только данные
нажавшего пользователя: все папки (включая «Входящие» и ИИ), заметки, исходные аудио, тексты,
историю диалогов и версии правок. Очередь уже принятых сообщений этого пользователя также очищается.
Настройки и данные использования ASR также удаляются. При следующем обращении бот предложит
назвать первую папку текстом или голосом. Во время обработки сообщений или экспорта нужно дождаться завершения
и повторить подтверждение.

В Telegram удаляются известные боту темы целиком со всеми сообщениями, включая неявные темы,
а затем остальные известные сообщения. Бот сохраняет только ID новых входящих и исходящих сообщений
для последующей очистки. Из старых данных используются все ранее сохранённые ID; API не позволяет
получить произвольную историю чата. Сообщения вне тем старше 48 часов и старые неучтённые сообщения
могут остаться: их можно убрать через «Очистить историю» в Telegram. Скачанные ZIP и копии в других
чатах остаются у пользователя. Ограничения: [deleteForumTopic](https://core.telegram.org/bots/api#deleteforumtopic),
[deleteMessage](https://core.telegram.org/bots/api#deletemessage).

Кнопки удаления и окончательного подтверждения красные. Удаление истории Telegram выполняется
однократно по известным ID: недоступные сообщения остаются, автоматических повторов и уведомлений
при перезапуске нет. Старые задания очистки Telegram снимаются без удаления новых записей.
Если очистка файлов не закончилась, приём новых заметок блокируется до её завершения;
это задание сохраняется в SQLite и продолжается после перезапуска.

## Экспорт

В `/export` доступны три варианта: «Всё: PDF + аудио», «Только тексты» и «Только аудио».
Формат текста меняется через «Настройки» → «Экспорт» → PDF / Markdown; выбор сохраняется отдельно для каждого
пользователя и действует и на весь архив, и на экспорт одной папки. По умолчанию используется PDF.

Вся история одной темы — один `history.pdf` или `history.md` в папке проекта, с записями в
хронологическом порядке. Документ включает полные тексты, ответы ИИ (если есть), проект и даты;
поддерживает кириллицу и перенос на несколько страниц. Шрифты DejaVu входят в пакет приложения.
Пустые папки сохраняются, а одноимённые проекты и записи различаются по ID.

В полном экспорте оригинальное аудио лежит в подпапке `audio` проекта; Markdown ссылается
на соответствующие файлы. Имена аудиофайлов включают дату, заголовок и ID записи.
«Только аудио» собирает отдельный ZIP с исходными аудиофайлами и их метаданными,
без расшифровок и текстовых заметок. Аудио не перекодируется.

Обычно отправляется один ZIP. При превышении настроенного предела (45 MB по умолчанию) архив
делится на независимые ZIP на границах файлов. Документ темы не дробится. Части можно распаковать в одну папку:
`manifest-001.json`, `manifest-002.json` и т. д. не перезаписывают друг друга.
Манифест содержит названия и псевдонимы проектов, пользовательские настройки, пути и контрольные суммы
файлов; для текстового/полного экспорта — также метаданные записей, точный исходный текст,
редактированный текст, историю версий и сохранённые ответы ИИ. PDF/Markdown показывает актуальный
текст и исходную расшифровку, если они различаются.
Секреты конфигурации и Telegram file IDs не экспортируются. Удалённые записи не включаются.

Экспорт использует снимок сохранённых записей на момент запуска. Если аудио ещё не загружено,
полная/аудиовыгрузка просит дождаться обработки или повторить её; тексты можно выгрузить отдельно.
Если сохранённое аудио пропало или повреждено, частичные ZIP не отправляются.

## Перенос между проектами

При переносе предлагаются только другие папки. После сохранения новой папки в общем архиве
бот удаляет исходные сообщения записи из Telegram. В целевой папке запись появится при её открытии.
Повторная отправка медиа и создание тем не требуются.
Папка новых записей при переносе старой не меняется. Уведомление о переносе показывается
в ответ на нажатие кнопки. Исходные аудио, расшифровки и правки ИИ сохраняются; экспорт
использует актуальную папку и содержимое. Очистка использует только сохранённые точные ID
и продолжается после перезапуска при временной ошибке Telegram.

Фото сохраняются в выбранной папке вместе с подписью, без распознавания или обращения к LLM.
По умолчанию исходное фото остаётся в чате без кнопок. Если включить «Кнопки у сообщений», бот заменит его копией с кнопками «Переместить», «Удалить», «ИИ» в одном ряду: «Переместить» или
«ИИ». После выбора ИИ отправь задание текстом или голосовым, например
«Распознай текст на картинке». Фото прикладывается к каждому запросу этого разговора;
подпись необязательна, оригинал сохраняется. «Завершить» возвращает к обычным заметкам.
Полный экспорт включает фото в каталоге `photos/`; режим «Только аудио» их исключает.
ИИ может править подпись и анализировать фото после чтения записи. Создание и редактирование
самих изображений доступно в чате. В чате выбери ИИ у фото и отправь
инструкцию, например «Замени фон на море»; для картинки с нуля попроси ИИ «Нарисуй…».
Нужен доступ ИИ «Чтение и запись». Результат сохраняется отдельной картинкой, оригинал остаётся.
Инструкцию можно отправлять сразу после фото: если оно ещё загружается, запрос дождётся загрузки
в очереди. После команды бот показывает «Думаю…», затем заменяет это сообщение ответом или
готовой картинкой. Длинный ответ приходит полностью, отдельными сообщениями после картинки.

## Провайдеры и данные

### Диалоги и действия ИИ

- `/ai` или «🤖 ИИ» открывает папку для разговоров. У любой папки можно переключить режим
  «Заметки / Диалог с ИИ». В режиме диалога голосовые и текст идут помощнику, без классификации папки.
- `/settings` → «Настройки ИИ» управляет обращением по имени (изначально выключено), именами, моделью и доступом к
  заметкам: выключен / чтение / чтение и запись. Имена редактируются, когда распознавание включено.
  Проверяется именно обращение в начале или конце; цитата и простое упоминание не должны его запускать.
  Если распознавание обращения недоступно или неоднозначно, сообщение остаётся заметкой.
- «ИИ» переводит уже принятую запись в запрос. Расшифровка используется повторно;
  аудио не отправляется в ASR второй раз. Повторное нажатие не создаёт второй запрос.
- Ответ на сообщение ИИ продолжает тот же разговор, даже вне ИИ-папки и при выключенном обращении
  по имени. Самостоятельное сообщение в обычной папке остаётся заметкой.
- `/newchat` или «Новый разговор» начинает чистый контекст, сохраняя прошлую историю. История ИИ
  доступна в карточке папки. Каждый ответ ИИ автоматически сохраняется отдельной записью «Ответ ИИ»
  в папке запроса. Ответы доступны в списке, поиске и PDF/Markdown-экспорте;
  их можно перемещать и удалять как обычные записи. Вопросы и контекст остаются в истории диалога.
  Ответ сохраняется до отправки в Telegram; повторная доставка и перезапуск не создают копий.
  При обновлении прежние успешные ответы из SQLite добавляются в архив с датой исходного запроса,
  без повторного обращения к модели или отправки в Telegram. Удалённые записи не восстанавливаются.
- ИИ может отвечать, анализировать, переписывать текст, искать и читать заметки, создавать и изменять
  их в существующих папках. Поиск пока по словам, включая русский регистр; семантического индекса нет.
  Записи другого пользователя недоступны. По умолчанию доступ к своим заметкам разрешает чтение и запись.
  Модель получает записи только через поиск и чтение по мере необходимости, а не весь архив сразу.
- По прямой просьбе ИИ переносит или удаляет одну выбранную запись без дополнительного подтверждения.
  На запрос допускаются максимум один перенос и одно удаление; лимит проверяется кодом и сохраняется
  при повторе запроса. `update_note` не может обходить лимит сменой папки. Неясную запись ИИ уточняет.
  `list_folders` возвращает все папки пользователя. Если точного названия или псевдонима нет, ИИ показывает
  «Новая папка», до четырёх похожих существующих папок и «Отмена» в Telegram.
  Новая папка создаётся только по кнопке, одновременно с переносом. Повторное нажатие ничего не дублирует;
  изменение записи, прав доступа или удаление выбранной папки требуют нового выбора.
  Удаляются только сохранённые ID сообщений этой записи; ограничения Telegram показываются в результате.
  Квитанция сохраняется вместе с изменением архива, незавершённая очистка продолжается после перезапуска.
- Изменение сохраняет отдельный текст и предыдущую версию; исходные аудио и `transcript.txt` не
  переписываются. Актуальный текст виден в карточке, поиске и PDF/Markdown истории в экспорте. «Отменить правку»
  восстанавливает предыдущую версию, если после неё запись не менялась. Перед изменением модель должна
  прочитать полную актуальную версию; перенос или другая правка во время генерации вызывает конфликт.
- На один запрос: до 8 шагов и 3 изменений заметок; текст запроса/заметки до 40000 символов.
  В контекст передаются последние 12 завершённых запросов в пределах 40000 символов. Полная история
  остаётся в SQLite, а модель получает признак сокращённого контекста. Массового удаления, произвольных файлов,
  shell, браузера и отправки сообщений другим людям у помощника нет.
- `assistant_models` в конфиге — дополнительные уже доступные этому аккаунту модели. Модель из `llm`
  включена всегда; по умолчанию используется она же. Пользователь выбирает модель в настройках,
  история хранится независимо от провайдера. Для нового транспорта реализуется интерфейс
  `respond(payload, model)` и `addressed(text, names, model)` с тем же проверяемым контрактом.

Диалоги работают через отдельный адаптер `CodexAssistant` и ограниченные операции приложения.
Миграция SQLite добавляет поля и таблицы без удаления старых заметок. Команда операции и квитанция
записываются в одной транзакции с изменением заметки: восстановление запроса после перезапуска не
повторяет уже выполненное изменение. Если ответ модели не получен после изменения, интерфейс всё равно
показывает квитанцию сделанного. Файлы заметок восстанавливаются из SQLite через очередь синхронизации.
При неизвестном результате отправки в Telegram автоматического повтора нет; сохранённый ответ можно
открыть из истории или «Опций». История хранится локально, а текущий контекст передаётся модели.

Отдельная проверка с реальной моделью использует только синтетический временный архив, не Telegram:

```bash
PYTHONPATH=src .venv/bin/python scripts/check_assistant.py --live
```

- Распознавание: Groq, `whisper-large-v3-turbo`, как в соседнем Helper bot. Оригинал отправляется
  multipart-файлом; он не заменяется преобразованной записью. `ffprobe` проверяет фактическую длительность.
- Папка определяется сохранённым выбором пользователя; заголовок берётся из первых 80 символов текста.
  `CodexRouter` и диагностические скрипты классификации сохранены для совместимости,
  но при обработке обычных заметок классификатор не вызывается.
- Диалог с ИИ и включённое обращение по имени используют штатный `codex exec` с входом ChatGPT.
  API-ключи и произвольные endpoints из окружения не наследуются; платного API-fallback нет.
- В адаптере Codex отключены пользовательские настройки CLI, plugins, apps, shell, браузер,
  memory, hooks и делегирование. Используются временная рабочая папка, read-only sandbox,
  ephemeral-режим и проверяемый JSON. Помощник получает только описанные выше операции приложения.
- Для запрошенной генерации изображения отдельный вызов включает `image_generation` и `code_mode_host`.
  По явному разрешению владельца только этот вызов использует `danger-full-access`: файловый
  помощник CLI не может перезапустить себя под systemd в sandbox-режиме. Ограничения самой службы
  не меняются; остальные инструменты остаются выключены. Текстовые вызовы сохраняют read-only sandbox.
  Отдельный `CODEX_HOME` ссылается только
  на существующую авторизацию; результат принимается только из его `generated_images`, декодируется
  и сохраняется как PNG с учётом лимитов архива. Права перепроверяются после генерации.
  Готовый файл сохраняется до транзакции записи и квитанции: повтор после сбоя сохранения использует
  этот файл. Прерванный вызов до получения файла можно повторить; он может заново вызвать генератор.
- На сервере CLI должен быть авторизован под пользователем сервиса для функций ИИ.
  Учётные данные не копируются приложением. Модель и усилие задаются в конфиге.

Аудио передаётся Groq; текст и запрошенные заметки передаются OpenAI только для функций ИИ. В первой версии нет шифрования
файлов приложения отдельным ключом: каталог закрыт UNIX-правами 0700, файлы создаются с 0600.
Не делай этот каталог общедоступным. Удаление отдельной записи подтверждается кнопкой и удаляет
запись/файлы из архива приложения, исходное сообщение и все известные части расшифровки в Telegram.
Если Telegram отклоняет удаление сообщения, бот сообщает о неполной очистке чата.
Пользовательские ZIP и копии в других чатах остаются у пользователя.
«Удалить всё» также удаляет темы и известные боту сообщения в Telegram в пределах его API.

В `data/notes/<user-id>/<note-id>/` находятся `voice.<исходное расширение>` или `photo.jpg`, `transcript.txt`, `note.md`.
Папки проектов хранятся в SQLite; экспорт строит физические папки проектов с безопасными именами.
`transcript.txt` сохраняет результат ASR без переписывания LLM. Заголовок берётся из начала текста.
Для фото `transcript.txt` хранит подпись. В Markdown добавляется ссылка на исходный файл.
Никакая автоматическая синхронизация с Obsidian/Notion не выполняется.

## Надёжность и пределы MVP

- SQLite WAL: очередь обновлений сохраняется до подтверждения offset Telegram.
- Повторное получение сообщения не создаёт вторую заметку. Запись получает устойчивый ID.
- При неожиданной внутренней ошибке входное обновление сохраняется в `updates` со статусом
  `failed`. Повтор требует проверки оператором: до ошибки часть действий могла уже выполниться.
- Аудио сохраняется атомарно до ASR; расшифровка фиксируется до функций ИИ. После перезапуска обработка
  продолжается с последнего сохранённого этапа. Провайдерский запрос при аварии между ответом и
  записью checkpoint может повториться; exactly-once биллинг внешних API не обещается.
- Перед отправкой результата сохраняется её намерение. Неопределённый результат отправки после
  обрыва связи не повторяется автоматически; заметка доступна в `/notes` и экспорте.
- Отправка расшифровки в исходную тему имеет checkpoint; повтор обработки не дублирует текст.
  Сообщение «Конвертирую в текст…» редактируется в саму расшифровку. Кнопки «Переместить», «Удалить», «ИИ» добавляются только при включённом переключателе «Кнопки у сообщений».
  Для длинного текста статус становится первой частью, продолжение отправляется отдельно, кнопка — под последней.
  Перед редактированием статус исключается из фоновой очистки, чтобы потеря ответа Telegram
  или перезапуск не удалили готовый текст. Перенос меняет папку архива без повторной публикации.
- Одна очередь обработки для частного MVP; команды работают во время ASR/LLM. Это не проверка
  пропускной способности публичного сервиса.
- До 20 MB и 30 минут на файл по умолчанию; фактический лимит времени задаётся в `limits`.
- Ограничены очередь, объём архива, число заметок/папок и длительность ASR за скользящие 24 часа.
  Лимиты Groq, общие с другими приложениями на том же ключе, здесь не учитываются глобально.
- Экспорт делится на ZIP до 45 MB на границах файлов. `manifest-*.json` содержит состояние записи
  и checksum включённого аудио. Если нужный сохранённый файл отсутствует или повреждён, экспорт
  завершается ошибкой, а не выдаётся как полный.
- Повтор ASR после ошибки запускается пользователем, максимум пять обработок на запись.

## Проверки

```bash
.venv/bin/ruff check src tests
.venv/bin/pytest -q
```

Тесты проверяют маршрутизацию и её границы, изоляцию пользователей, восстановление очереди,
оригиналы и экспорт, сбои провайдеров и отсутствие автоматического повтора неопределённой отправки.
Они не отправляют реальные сообщения и не расходуют Groq/OpenAI.

Для службы пользователя systemd есть `deploy/voice-memory-bot.service.in`. Подставляются точные
`@APP_DIR@`, `@CONFIG@`, `@SECRETS@`; CLI запускается под тем же пользователем, у которого выполнен вход ChatGPT.
Не направляй новый сервис на токен/каталог другого бота.

Источники контрактов: [Telegram Bot API](https://core.telegram.org/bots/api),
[Groq Speech to Text](https://console.groq.com/docs/speech-to-text),
[Codex non-interactive](https://learn.chatgpt.com/docs/non-interactive-mode),
[Codex authentication](https://learn.chatgpt.com/docs/auth).

Видеокружки Telegram автоматически расшифровываются как голосовые; оригинальный MP4 сохраняется в архиве.
В `/settings` → «Записей на странице» можно выбрать 10, 20, 50 или 100 записей.
Выбор сохраняется отдельно для каждого пользователя и применяется при следующем открытии папки.
В начале просмотра показан номер страницы; наши стрелки влево/вправо открывают предыдущую/следующую.
На первой странице нет стрелки влево, на последней — вправо.

Нижняя клавиатура показывает до четырёх папок: закреплённые на первой странице, остальные — по стрелкам ⬅️ / ➡️.
### Отображение активной папки в Telegram

Кнопка закреплённой папки или открытие папки очищает известные боту сообщения
в текущем чате/теме и показывает сохранённое содержимое выбранной папки
(по 20 записей на страницу по умолчанию, тексты, фото и ответы ИИ). Новые записи сразу
направляются в выбранную папку. Аудио доступно через экспорт. Архив не удаляется.
Если идёт обработка, очистка откладывается до её завершения.

Каждые 5 секунд бот проверяет возраст самого старого отображаемого сообщения.
Через 24 часа от отправки он удаляет все известные сообщения пользователя во всех темах
и восстанавливает последний открытый экран (настройки, меню, папку и её страницу) без звукового
уведомления. Активность и редактирование сообщений не сбрасывают этот срок;
состояние сохраняется в SQLite и восстанавливается после перезапуска.
Telegram может отказать в удалении сообщений старше 48 часов: длительная
недоступность сервера или незавершённая обработка не позволяют гарантировать
очистку. Такие сообщения остаются для ручного удаления. Неизвестные боту
сообщения не затрагиваются. Архив и сами темы Telegram не удаляются.

### Папки и названия голосом

Новый пользователь начинает без папок: бот спрашивает название первой. Можно
удалить любую папку, включая прежние «Входящие» и последнюю. Записи и оригиналы
при этом остаются в архиве без видимой папки; они доступны через поиск и общий
экспорт. Из карточки запись можно перенести в новую папку. «Удалить всё»
по-прежнему удаляет и архив. Удалённые папки не восстанавливаются автоматически.

На вопрос о названии можно ответить текстом, голосовым, аудио или видеокружком
до одной минуты. Groq расшифровывает запись, затем подписочная Luna извлекает
название: «Давай назовём папку Test 2» → «Test 2». Одно сообщение меняет статусы,
а выбранная новая папка сразу появляется на текущей странице нижних кнопок.
Оригинал и расшифровка команды сохраняются отдельно от заметок. Для названия
используется текущая `llm.model` с `low`; отдельная настройка `folder_name_model`
позволяет выбрать другую доступную модель. При ошибке бот предлагает повторить
голосовое или написать название текстом. При неоднозначном названии показывает, что расслышал.
В запросе названия и статусах создания нет кнопки «Отмена»; выйти можно через меню или `/cancel`.
Для распознавания названий передаётся [контекст Groq](https://console.groq.com/docs/speech-to-text#prompting-guidelines),
а Luna учитывает искажения вводной части команды, сохраняя само название.

Переключение очищает все известные сообщения пользователя, включая команды и
старые темы, и показывает активную папку. Остатки прежнего задания удаления
Telegram-тем не блокируют новый архив. Нижняя клавиатура обновляется до очистки.

### Нижнее меню Telegram

Навигация и настройки открываются в нижней клавиатуре: «☰ Меню», «📂 Все папки», поиск, экспорт, настройки ИИ и папки. «⬅️ Назад» отменяет ввод и возвращает на предыдущий уровень, «🏠 Главная» возвращает к ярлыкам папок. Списки разбиты на страницы; в настройках отмечен текущий выбор. В «⚙️ Настройки» есть переключатель «Кнопки у сообщений», по умолчанию выключенный для каждого пользователя. Без кнопок новые текстовые сообщения и фото сохраняются в архив, а оригиналы остаются в чате без копирования и удаления; голосовые по-прежнему расшифровываются. При включении сохраняется прежняя логика: текст и фото заменяются копиями с кнопками «Переместить», «Удалить», «ИИ», у расшифровки также появляются кнопки. Выбор сохраняется после перезапуска и применяется к новым сообщениям и последующим просмотрам архива.

Telegram обновляет нижнюю клавиатуру новым сообщением. В чате остаётся одна короткая подпись текущего раздела без кнопок: удаление последнего сообщения с клавиатурой сбрасывает её в Telegram Web. После успешного перехода бот удаляет предыдущую подпись и нажатия кнопок по полученным ID. Подсказки ввода, справка и предупреждения об удалении остаются до следующего перехода. Состояние клавиатуры сохраняется в SQLite: после перезапуска её кнопки не превращаются в заметки. Подтверждения удаления истекают и требуют повторного открытия после перезапуска.

### Options и исходники папки

Нижняя кнопка **⚙️ Options** открывает действия с текущей папкой и заменяет
клавиатуру выбора папок: переименовать, удалить с подтверждением, скачать
исходники. **🏠 Главная** возвращает выбор; **☰ Меню** открывает общие действия.
Удаление папки оставляет её записи в архиве без папки. Ввод названия отменяется
при выходе из настроек или переключении папки.

**📦 Скачать исходники** отправляет ZIP только выбранной папки. Внутри — исходные
голосовые, кружочки, фото, видео и произвольные файлы без перекодирования,
исходные `text.txt` и `caption.txt`, `message.json` с метаданными и манифест SHA-256.
ИИ-правки и ответы не подменяют исходный текст. Новые сообщения сохраняют точные
пробелы, подписи и имена вложений; для старых записей используются ранее сохранённые
оригиналы и исходный текст (`legacy_source` в метаданных, если исходное сообщение
не было сохранено). Медиа скачиваются на диск до очистки сообщения в Telegram.
Файл без успешной загрузки не удаляется из чата; неполный ZIP не отправляется.
Настройки и команды управления папками не становятся заметками.

По умолчанию сохраняется облачный Bot API: входящие файлы до 20 MB и ZIP-части
до 45 MB. Для крупных архивов поддерживается **локальный Bot API**:
`telegram_api_base` (например, `http://127.0.0.1:8083`) и `telegram_file_root`
(абсолютный каталог файлов API, доступный пользователю службы бота).
Те же значения можно передать через `VOICE_MEMORY_TELEGRAM_API_BASE` и
`VOICE_MEMORY_TELEGRAM_FILE_ROOT`. Абсолютные пути из `getFile` принимаются только
внутри этого каталога; оригиналы копируются в собственный архив бота.
Можно повысить `limits.export_part_bytes` до `1950000000` и
`limits.max_file_bytes` до `1900000000`, учитывая пользовательскую квоту хранения.
ZIP больше лимита разбивается на независимые части на границах файлов.
Один исходник с метаданными должен помещаться в часть. Аудио больше 24 MB остаётся
в архиве, но не отправляется в Groq для распознавания.

Переход на локальный API выполняется при остановленном poller после сохранения
ожидающих облачных обновлений и вызова cloud `logOut`. Нельзя одновременно
запускать cloud/local poller; Telegram ограничивает возврат в облако после
`logOut` на 10 минут. Настройка другого бота и его API-служба не изменяются.
Ограничения: [официальный Bot API](https://core.telegram.org/bots/api#using-a-local-bot-api-server).

Ответ текстом, голосовым или фото на сообщение запускает ИИ: текст исходного сообщения передаётся как контекст, голосовое сначала расшифровывается, фото прикладывается к запросу. Ответ на реплику ИИ продолжает существующий разговор.

При сохранении нового содержательного ответа в архиве остаётся только последний ответ ИИ этого разговора. Предыдущие ответы переходят в служебную историю: сообщения Telegram, их ID, контекст обсуждения и существующие файлы сохраняются, но старые ответы больше не показываются как заметки, не находятся поиском и не включаются отдельными ответами в экспорт. Ошибка запроса или подтверждение переноса/удаления не вытесняет последний сохранённый ответ. Замена фиксируется вместе с новым ответом в одной транзакции; повторное выполнение старого запроса после перезапуска не возвращает устаревший ответ в архив.

При каждом ответе ИИ получает точные ID исходного сообщения и записи, а также ID пользовательских реплик и своих ответов в обсуждении. `list_conversation` возвращает всю цепочку независимо от длины истории: исходную запись, реплики и ответы, кроме текущей выполняемой команды. `move_notes` и `delete_notes` принимают список ID без ограничения количества; `move_note` и `delete_note` продолжают работать для отдельных записей. Для переноса всей цепочки достаточно «перенеси всё обсуждение в …». Один выбор новой или существующей папки применяется ко всему пакету. Бот проверяет владельца, доступ и версии всех сообщений до изменения, а очистку Telegram возобновляет по отдельным квитанциям. Перенесённые реплики видны в папке вместе с ответами. Подтверждения операций показываются в чате, но не создают новых заметок.


### Правки сообщений в Telegram

Правки текста сохранённой заметки и подписи к медиа обновляют существующую запись
и файлы архива. Команды и запросы к ИИ при правке повторно не выполняются.
Расшифровка аудио сохраняется отдельно от подписи. Замена самого медиафайла
этим обработчиком не поддерживается.
Обычный Bot API не сообщает об удалении сообщений пользователем в личном чате:
для удаления сохранённой заметки используй кнопку «Удалить» в боте.

## Синие эмодзи Blue Tape

Набор [Audio Notes · Blue Tape](https://t.me/addemoji/AudioNotesBlueTape_by_your_audio_notes_bot)
содержит 41 оригинальный статичный эмодзи 100×100 на прозрачном фоне. Он опубликован для
владельца бота; SVG-исходники, PNG, палитра и квитанция публикации находятся в
`assets/emoji/blue_audio_v1/`. Идентификаторы для исполнения — `src/voice_memory_bot/emoji_pack.json`.

Сообщения и подписи используют Telegram custom-emoji entities, кнопки — `icon_custom_emoji_id`.
Текст заметок и архив не переписываются. Подписи нижней клавиатуры сохраняются до отправки
и сопоставляются с прежними действиями; устаревшие кнопки не превращаются в заметки.
При явном отказе Telegram использовать custom emoji выполняется одна отправка с обычным оформлением;
неопределённый результат доставки не повторяется. Telegram не поддерживает custom emoji в
описаниях команд слева и подсказке поля ввода: описания команд без значков, подсказка содержит имя папки.

Для пересборки иллюстраций: `python3 scripts/build_blue_emoji.py` (Pillow и системные librsvg/Cairo).
`publish_blue_emoji.py` публикует набор с явно заданным `--owner`, проверяет владельца по конфигу,
сохраняет квитанцию и не заменяет существующие эмодзи. Токены берутся из приватного `--secrets`.
