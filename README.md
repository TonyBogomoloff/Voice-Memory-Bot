# Voice Memory Bot

Личный Telegram-архив голосовых и текстовых заметок по проектам. MVP: нативные темы в личном
чате, управление папками кнопками, голосовой выбор проекта, поиск, экспорт TXT/Markdown/аудио.

## Запуск

Нужны Python 3.11+, `ffprobe` из ffmpeg и актуальный Codex CLI с `--ignore-user-config`.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pip install --no-deps -e .
cp config.example.json config.json
```

В `config.json` заполни `allowed_user_ids` (числовые Telegram ID),
`bot_token_your_audio_notes` и `groq_voice`. Конфиг исключён из Git. Файл должен быть доступен
только пользователю сервиса: `chmod 600 config.json`.

Для существующего общего конфига секреты можно не копировать:

```bash
.venv/bin/python -m voice_memory_bot check --config config.json --secrets /точный/путь/config.json --live
.venv/bin/python -m voice_memory_bot run --config config.json --secrets /точный/путь/config.json
```

В общем файле читаются только `bot_token_your_audio_notes` и `groq_voice`. Параметры приложения,
список пользователей и `data_dir` читаются из локального `--config`. Пустой список пользователей
запрещён: этот MVP рассчитан на частный доступ через подписку владельца.

`check --live` проверяет конфиг, `getMe`, наличие webhook и тип входа Codex. Он не отправляет
сообщения и не доказывает работу распознавания или генерации. Существующий webhook не удаляется
автоматически, а второй процесс для того же `data_dir` не запускается.

## Telegram

В BotFather включи Threaded Mode / темы в личном чате. Для постоянных проектов удобно включить
«Disallow users to create new threads»: новые проекты всё равно создаются кнопкой «Новая папка»
или `/new Название`, а Telegram не создаёт отдельную тему для каждого сообщения из общего вида.
Существующие темы можно выбирать напрямую в Telegram. Если создание тем пользователями разрешено,
бот также принимает события создания и переименования тем.
Неявные темы, автоматически созданные Telegram при отправке сообщения, не становятся отдельными
папками: записи из них используют выбранный проект или «Входящие».

Без включённых тем работают виртуальные папки с кнопками. Включение тем допускает доплату Telegram
15% с покупок за Stars внутри бота; платежей в этом MVP нет.

- `/new Игра` — создать проект и его тему.
- `/folders` — проекты, псевдонимы, переименование, выбор папки для общего чата.
- Голосовое/аудиофайл/текст в теме — новая заметка этого проекта.
- Для аудио бот показывает временное «Конвертирую в текст…», удаляет его после распознавания
  и сразу присылает полную расшифровку отдельным сообщением, не дожидаясь выбора проекта через LLM.
  Длинная расшифровка приходит несколькими текстовыми сообщениями без обрезки.
- Под расшифровкой — «Опции» → «Переместить». Выбор проекта меняет только кнопки,
  сохраняя текст сообщения. Остальные инструменты архива доступны через `/notes` и `/folders`.
- «Сохрани в проект Игра» в начале или конце записи — явный выбор проекта.
- Простое упоминание проекта не должно менять папку.
- Неизвестное имя, конфликт или недоступная LLM — «Входящие» и ручной выбор.
- Для неизвестного имени можно подтвердить создание новой папки кнопкой в карточке.
- `/search слова` — поиск по заголовку и исходной расшифровке, включая русский регистр.
- `/export` — весь архив; экспорт отдельной папки доступен в её карточке.

Перенос изменяет проект в архиве и публикует аудио и полную расшифровку в выбранной теме.
При голосовой команде выбора другого проекта такая же копия появляется после определения проекта.
При ручном переносе исходные голосовое и все части расшифровки удаляются из той темы, где выбран
перенос, только после подтверждённой доставки в выбранную папку. ID сообщений сохраняются;
подтверждение переноса показывается всплывающим уведомлением, без сообщения в истории.
прерванная очистка продолжается после перезапуска без повторной отправки записи. Telegram может
отказать в удалении сообщений старше 48 часов; тогда бот сообщает об этом отдельно.
Фото сохраняются в выбранной папке вместе с подписью, без распознавания или обращения к LLM.
Под исходным фото бот отправляет отдельное сообщение «📷 Фото» с кнопкой «Опции» → «Переместить».
При переносе фото и его подпись появляются в выбранной теме, а исходное фото и сообщение с кнопкой удаляются.
Изменение/удаление темы самим пользователем
не означает удаление архива. Если Telegram явно отклонил первую отправку в удалённую тему,
бот создаёт тему заново. Неопределённая отправка или ошибка после публикации части записи
автоматически не повторяется; архив остаётся доступен через `/folders`.

## Провайдеры и данные

- Распознавание: Groq, `whisper-large-v3-turbo`, как в соседнем Helper bot. Оригинал отправляется
  multipart-файлом; он не заменяется преобразованной записью. `ffprobe` проверяет фактическую длительность.
- Классификация: `CodexRouter`, по умолчанию `gpt-5.6-luna`, reasoning effort `low`.
  Это стартовая настройка, а не результат сравнения скорости всех доступных моделей.
- Используется штатный `codex exec` с входом ChatGPT. API-ключи и произвольные endpoints из окружения
  не наследуются; платного API-fallback нет. Авторизация проверяется до каждого вызова.
- Пользовательские настройки CLI, plugins, apps, shell, браузер, memory, hooks и делегирование
  отключены для классификатора. Используются временная рабочая папка, read-only sandbox,
  ephemeral-режим и проверяемый JSON. У LLM нет функций управления архивом.
- На сервере CLI должен быть авторизован под пользователем сервиса. Наличие авторизации на другом
  компьютере не подтверждает её наличие на сервере. Учётные данные не копируются приложением.
- Модель и усилие задаются в конфиге. Для будущего провайдера достаточно реализовать
  `classify(transcript, folders)` с тем же контрактом и подключить адаптер в `cli.py`.

Аудио передаётся Groq, расшифровка и имена проектов — OpenAI. В первой версии нет шифрования
файлов приложения отдельным ключом: каталог закрыт UNIX-правами 0700, файлы создаются с 0600.
Не делай этот каталог общедоступным. Удаление подтверждается кнопкой и удаляет запись/файлы из
архива приложения; отдельные копии в Telegram и пользовательские ZIP остаются у пользователя.

В `data/notes/<user-id>/<note-id>/` находятся `voice.<исходное расширение>` или `photo.jpg`, `transcript.txt`, `note.md`.
Папки проектов хранятся в SQLite; экспорт строит физические папки проектов с безопасными именами.
`transcript.txt` сохраняет результат ASR без переписывания LLM. Заголовок генерируется отдельно.
Для фото `transcript.txt` хранит подпись. В Markdown добавляется ссылка на исходный файл.
Никакая автоматическая синхронизация с Obsidian/Notion не выполняется.

## Надёжность и пределы MVP

- SQLite WAL: очередь обновлений сохраняется до подтверждения offset Telegram.
- Повторное получение сообщения не создаёт вторую заметку. Запись получает устойчивый ID.
- При неожиданной внутренней ошибке входное обновление сохраняется в `updates` со статусом
  `failed`. Повтор требует проверки оператором: до ошибки часть действий могла уже выполниться.
- Аудио сохраняется атомарно до ASR; расшифровка фиксируется до LLM. После перезапуска обработка
  продолжается с последнего сохранённого этапа. Провайдерский запрос при аварии между ответом и
  записью checkpoint может повториться; exactly-once биллинг внешних API не обещается.
- Перед отправкой результата сохраняется её намерение. Неопределённый результат отправки после
  обрыва связи не повторяется автоматически; заметка доступна в `/notes` и экспорте.
- Отправка расшифровки в исходную тему имеет отдельный checkpoint от публикации в папке проекта:
  повтор выбора папки не дублирует уже отправленный текст. ID временного статуса сохраняется в БД,
  чтобы удалить его и после перезапуска; временная ошибка удаления не блокирует расшифровку.
- Одна очередь обработки для частного MVP; команды работают во время ASR/LLM. Это не проверка
  пропускной способности публичного сервиса.
- До 20 MB и 30 минут на файл по умолчанию; фактический лимит времени задаётся в `limits`.
- Ограничены очередь, объём архива, число заметок/папок и длительность ASR за скользящие 24 часа.
  Лимиты Groq, общие с другими приложениями на том же ключе, здесь не учитываются глобально.
- Экспорт делится на ZIP до 45 MB на границах заметок. `manifest.json` содержит состояние записи
  и checksum включённого аудио. Если нужный сохранённый файл отсутствует или повреждён, экспорт
  завершается ошибкой, а не выдаётся как полный.
- Повтор ASR/выбора папки запускается пользователем, максимум пять обработок на запись.

## Проверки

```bash
.venv/bin/ruff check src tests
.venv/bin/pytest -q
```

Тесты проверяют маршрутизацию и её границы, изоляцию пользователей, восстановление очереди,
оригиналы и экспорт, сбои провайдеров и отсутствие автоматического повтора неопределённой отправки.
Они не отправляют реальные сообщения и не расходуют Groq/OpenAI.

Для службы пользователя systemd есть `deploy/voice-memory-bot.service.in`. Подставляются точные
`@APP_DIR@`, `@CONFIG@`, `@SECRETS@`; CLI запускается под тем же пользователем, у которого выполнен вход ChatGPT.
Не направляй новый сервис на токен/каталог другого бота.

Источники контрактов: [Telegram Bot API](https://core.telegram.org/bots/api),
[Groq Speech to Text](https://console.groq.com/docs/speech-to-text),
[Codex non-interactive](https://learn.chatgpt.com/docs/non-interactive-mode),
[Codex authentication](https://learn.chatgpt.com/docs/auth).
